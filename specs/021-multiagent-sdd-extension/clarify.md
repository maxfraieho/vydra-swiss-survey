## 1. Конституція §3 (фантомні `/speckit.*` команди)

**Рішення: Варіант C — two-layer, явно задекларований.**

Native Spec Kit встановлюється для `claude` + `codex` (обидва `Multi-install
Safe: yes`). Самописний шар `/sdd:*` лишається як project-level семантичний
шар. Конституція §3 переписується у формат мапінгу «фаза → native primitive →
project command → shared skill» (див. `plan.md` §1.3.5). Правило пріоритету:
конституція = інваріанти, методологія = процедура, native-команди = транспорт.

Обґрунтування: downgrade (Варіант A) викидає апстрім-інфраструктуру Spec Kit
(templates, presets, hash-manifest) без потреби — 0-ризикова відмова від
можливостей заради 0-ризикової відсутності роботи. Two-layer дає Codex
офіційний native-шлях і не ламає наявні 9 `/sdd:*` команд.

## 2. Де тестувати P5 (`specify integration install`)

**Рішення: прямо на `astryx-ui-refactor` (live), не на master-клоні й не на
окремій гілці.**

Явне рішення користувача. Обґрунтування користувача: Termux-контур зараз
неактуальний, вся розробка фактично йде на dev-184 (в т.ч. живий прод-процес
на порту 5005 обслуговується саме з цього чекауту). Мітигація ризику
(install може перезаписати `constitution.md`):
- Перед `specify integration install` — `cp .specify/constitution.md
  .specify/constitution.md.pre-install-backup` (поза git, локально).
- Після кожного install-кроку — `git status` + `git diff --stat
  .specify/constitution.md`; якщо файл зачеплено — негайний
  `git checkout -- .specify/constitution.md` і відновлення з backup.
- Прод-процес (`astryx_survey_server.py`, порт 5005) не залежить від
  `.specify/`/`.claude/` — install не може його зачепити напряму. Перевірка
  `curl 127.0.0.1:5005/ops` до/після кожної install-команди (acceptance
  критерій §10.9 з `plan.md`).

## 3. AGY — рукописний шлях (не `specify integration install agy`)

**Підтверджено, без додаткової перевірки `specify integration info agy`.**
`Multi-install Safe: no` — достатня підстава уникати офіційного installer'а
для AGY. 5 skill-файлів у `.agents/skills/sdd-*/` (спільні з Codex) повністю
покривають потребу без офіційної інтеграції.

## 4. R1 — дублювання скілів `.agents/skills/` vs `.claude/skills/`

**Рішення: `.agents/skills/` — єдине джерело правди, без дублювання.**

`AGENTS.md` вже прямо каже: MUST прочитати `.agents/skills/sdd-workflow/
SKILL.md` — тобто Claude Code в цьому проєкті вже де-факто читає з
`.agents/skills/`, окремого дзеркала в `.claude/skills/` для SDD-скілів не
потрібно. `sdd_verify.sh` (Фаза P7) отримає перевірку паритету лише для
не-SDD скілів, що вже існують в обох деревах (не розширювати дублювання
новими файлами).

## 5. Арбітр — ключ і модель

**Рішення:** ключ у `~/.vydra-survey-profiles/sdd_judge.env`
(`SDD_JUDGE_KEY=...`), поза git (та ж директорія, що й інші секрети проєкту
— Інваріант 1 конституції). Модель — `SDD_JUDGE_MODEL` env, дефолт
визначається після живого `GET /v1/models` на проксі (зараз `401`, потрібен
робочий ключ — це блокер Фази P8, не P0-P4).

## 6. Git-hook шлях

**Рішення:** `core.hooksPath=.githooks`, трекований `.githooks/pre-commit`.
Версіонується разом з репо, приїжджає автоматично на будь-який чекаут
(включно з master-клоном на 5006, якщо туди колись знадобиться).

## 7. Номер specs/

**Рішення: `021`**, не заповнювати «дірку» `019`. Глобальний максимум за
всю історію (`git log --all`) = `020`. `019` ніколи не існував і заповнення
дірки заднім числом плутатиме нумерацію більше, ніж послідовний `021`.

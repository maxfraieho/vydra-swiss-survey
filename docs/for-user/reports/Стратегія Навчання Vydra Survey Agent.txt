Для зведення трудомісткості навчання до 1–2 кліків без необхідності ручного кодування селекторів пропонується трикомпонентна оптимізація.

2. Математика та Алгоритми Промоції Правил (Rule Promotion & Confidence Scoring)
Використання детермінованого лічильника успішних застосувань (N \ge 3) без урахування загального обсягу вибірки та часової актуальності створює суттєвий ризик передчасної промоції помилкових правил або застрягання коректних правил у тіньовому статусі (shadow). Для математично обґрунтованого переведення правил із shadow у active (promoted) розроблено гібридну оціночну модель.
Інтервал Довіри Вілсона (Wilson Score Interval)
Для оцінки ймовірності успіху p правила на основі біноміальних результатів (W — успішні прогони/wins, L — збої/losses) застосовується нижня межа інтервалу Вілсона, яка є стійкою для вибірок малого обсягу:
\text{Confidence}_{\text{Wilson}}(W, L) = \frac{\hat{p} + \frac{z^2}{2N} - z \sqrt{\frac{\hat{p}(1-\hat{p})}{N} + \frac{z^2}{4N^2}}}{1 + \frac{z^2}{N}}
Де:
* N = W + L — загальна кількість застосувань правила.
* \ha[span_12](start_span)[span_12](end_span)t{p} = \frac{W}{N} — спостережувана частка успіхів.
* z =[span_13](start_span)[span_13](end_span) 1.96 — квантиль стандартного нормального розподілу для рівня довіри 95\%.
Байєсівська Оцінка з Пріорним Бета-Розподілом та Часовим Згасанням
Правило моделюється як Бета-біноміальний процес Beta(\alpha, \beta). Початковий пріор для тіньових правил (shadow_rules від self_reflection) приймається як \alpha_0 = 1, \beta_0 = 1 (рівномірний пріор). Для правил, сформованих безпосередньо людиною (human_override), встановлюється пріор \alpha_0 = 4, \beta_0 = 1.
Оскільки веб-інтерфейси опитувань можуть змінюватися, давні успішні прогони повинні мати меншу вагу. Вводиться коефіцієнт експоненційного часового згасання \lambda = 0.05 (за день) для ефективних підрахунків W_{\text{eff}} та L_{\text{eff}}:
W_{\text{eff}} = \sum_{i=1}^{k} e^{-\lambda (t_{\text{now}} - t_i)}, \quad L_{\text{eff}} = \sum_{j=1}^{m} e^{-\lambda (t_{\text{now}} - t_j)}
Математичне сподівання Байєсівської довіри обчислюється за формулою:
E[\theta] = \frac{\alpha_0 + W_{\text{eff}}}{\alpha_0 + \beta_0 + W_{\text{eff}} + L_{\text{eff}}}
Ентропійний Оцінювач Варіативності Рішень (Entropy Rating)
Для оцінки стабільності рішень візуальної моделі Gemma відносно тексту сторінки обчислюється шеннонівська ентропія вибраних дій A для одного патерну P:
H(A \vert{} P) = -\sum_{a \in A} P(a \vert{} P) \log_2 P(a \vert{} P)
Висока ентропія (H(A \vert{} P) > 0.8) свідчить про високу нестабільність дій моделі на даній сторінці, що блокує автоматичну промоцію правила незалежно від підрахунку N, вимагаючи обов'язкової верифікації тутором.
Критерії Автоматичної Промоції Правила (Promote Gate)
Тіньове правило переводиться у статус active тільки при одночасному виконанні наступних умов:
1. Кількість унікальних сесій (різних run_id), де відпрацювало правило: R_{\text{u[span_17](start_span)[span_17](end_span)nique}} \ge 3.
2. Нижня межа інтервалу Вілсона: \text{Confidence}_{[span_39](start_span)[span_39](end_span)\text{Wilson}} \ge 0.70.
3. Ентропія варіантів дій: H(A \vert{} P) \le 0.35.
4. Відсутність зареєстрованих поразок (L_{\text{eff}} = 0) або співвідношення W_{\text{eff}} / L_{\text{eff}} \ge 5.0.
Гарантія Ізоляції та Запобігання Поширенню Хибних Оверрайдів
Для запобігання ситуації, коли правило, створене для конкретного опитування на хості (наприклад, meinungsplatz.ch), псує інші опитування того ж хоста, вводиться 4-рівнева ієрархічна система ізоляції.

# Advanced Confidence Scoring and Rule Promotion Engine in persona_graph_memory.py
import math
import time
from typing import Dict, Any, List, Set

def calculate_rule_confidence_and_gate(
   wins: int,
   losses: int,
   history_events: List[Dict[str, Any]],
   source: str,
   unique_run_ids: Set[str],
   entropy: float = 0.0
) -> Dict[str, Any]:
   """
   Computes Wilson Score lower bound, Bayesian expected confidence with exponential time decay,
   and validates strict promotion gate conditions.
   """
   now = time.time()
   decay_rate_per_day = 0.05
   decay_rate_per_sec = decay_rate_per_day / 86400.0
   
   w_eff = 0.0
   l_eff = 0.0
   
   for event in history_events:
       age_seconds = max(0.0, now - event.get("timestamp", now))
       weight = math.exp(-decay_rate_per_sec * age_seconds)
       if event.get("outcome") == "win":
           w_eff += weight
       else:
           l_eff += weight

   # Set Bayesian prior based on rule origin
   alpha_0 = 4.0 if source == "human_override" else 1.0
   beta_0 = 1.0
   
   bayes_score = (alpha_0 + w_eff) / (alpha_0 + beta_0 + w_eff + l_eff)
   
   # Wilson Score Interval (Lower bound calculation)
   total_eff = w_eff + l_eff
   if total_eff == 0.0:
       wilson_lower = 0.0
   else:
       z = 1.96  # 95% confidence level
       p_hat = w_eff / total_eff
       denominator = 1.0 + (z**2) / total_eff
       center = p_hat + (z**2) / (2.0 * total_eff)
       spread = z * math.sqrt((p_hat * (1.0 - p_hat) / total_eff) + (z**2) / (4.0 * (total_eff**2)))
       wilson_lower = (center - spread) / denominator

   n_unique = len(unique_run_ids)
   should_promote = (
       n_unique >= 3 and
       wilson_lower >= 0.70 and
       l_eff == 0.0 and
       entropy <= 0.35
   )
   
   return {
       "wilson_lower": round(wilson_lower, 4),
       "bayes_score": round(bayes_score, 4),
       "effective_wins": round(w_eff, 2),
       "effective_losses": round(l_eff, 2),
       "unique_runs": n_unique,
       "should_promote": should_promote
   }

3. Багатомовний Парсинг та Робота з Диакритикою (Multi-lingual Survey Engines)
Швейцарські опитувальні платформи динамічно змінюють мову інтерфейсу між французькою, німецькою, італійською та англійською мовами (наприклад, Continuer / Weiter / Fortfahren / Next / Seguito / Avanti), часто використовуючи спецсимволи та диакритику (é, è, à, ç, ä, ö, ü, ß). Пряме співставлення підрядків у cdp_client.py призводить до пропускання елементів навігації та варіантів відповідей.
Стратегія Семантичної Нормалізації та Пошуку Елементів
Для вирішення цієї проблеми розроблено багаторівневий конвеєр нормалізації та нечіткого (fuzzy) зіставлення рядків.
Конвеєр обробки тексту починається з витягування сирого рядка з DOM або CDP. На першому етапі виконується Unicode NFD (Normalization Form Canonical Decomposition) декомпозиція, яка відокремлює базові літери від диакритичних знаків. Далі спеціальний транслітератор конвертує специфічні мовні символи (наприклад, німецькі умляути ä \to ae, ö \to oe, ü \to ue, ß \to ss) та видаляє HTML-знесення ( , \xa0).
Після приведення тексту до канонічної нижньорегістрової форми виконується багаторівневе зіставлення: спочатку перевіряється точний збіг, потім обчислюється відстань Джаро-Вінклера та Левенштейна, а для складних речень використовується косинусна подібність текстових ембеддингів.
Алгоритм Семантичного Зіставлення в cdp_client.py
1. Unicode NFD Декомпозиція: Символи з диакритикою розкладаються на базовий символ та відокремлений диакритичний знак, після чого знаки видаляються регулярним виразом.
2. Заміна Німецьких Умляутів: Символи ä, ö, ü, ß конвертуються у стандартні графічні еквіваленти (ae, oe, ue, ss).
3. Нечітке Співставлення (Fuzzy String Matching): Обчислюється комбінована метрика відношення відстані Левенштейна та подібності Джаро-Вінклера (поріг \ge 0.82).
4. Словник Навігаційних Интентив: Застосовується крос-мовний мапінг стандартних дій (наприклад, continue \to continuer, weiter, fortfahren, next, suivant, avanti, submit).
# Multi-lingual text normalization and fuzzy DOM target lookup for cdp_client.py
import re
import unicodedata
from typing import List, Optional, Dict, Any

def normalize_survey_text(text: str) -> str:
   """
   Performs full Unicode NFD normalization, strips diacritics, converts German umlauts,
   removes extra spaces and HTML entities.
   """
   if not text:
       return ""
   
   text = text.replace(" ", " ").replace("\xa0", " ")
   
   # Custom map for German umlauts before stripping accents
   umlaut_map = {"ä": "ae", "ö": "oe", "ü": "ue", "Ä": "Ae", "Ö": "Oe", "Ü": "Ue", "ß": "ss"}
   for char, replacement in umlaut_map.items():
       text = text.replace(char, replacement)
       
   normalized = unicodedata.normalize("NFD", text)
   stripped = "".join(c for c in normalized if unicodedata.category(c) != "Mn")
   
   cleaned = re.sub(r"[^\w\s]", " ", stripped).lower()
   return re.sub(r"\s+", " ", cleaned).strip()

def jaro_winkler_similarity(s1: str, s2: str) -> float:
   """Calculates Jaro-Winkler similarity between two normalized strings."""
   if s1 == s2:
       return 1.0
   len1, len2 = len(s1), len(s2)
   if len1 == 0 or len2 == 0:
       return 0.0
   
   match_bound = max(len1, len2) // 2 - 1
   s1_matches = [False] * len1
   s2_matches = [False] * len2
   
   matches = 0
   transpositions = 0
   
   for i in range(len1):
       start = max(0, i - match_bound)
       end = min(i + match_bound + 1, len2)
       for j in range(start, end):
           if s2_matches[j]:
               continue
           if s1[i] != s2[j]:
               continue
           s1_matches[i] = True
           s2_matches[j] = True
           matches += 1
           break
           
   if matches == 0:
       return 0.0
       
   k = 0
   for i in range(len1):
       if not s1_matches[i]:
           continue
       while not s2_matches[k]:
           k += 1
       if s1[i] != s2[k]:
           transpositions += 1
       k += 1
       
   transpositions //= 2
   jaro = (matches / len1 + matches / len2 + (matches - transpositions) / matches) / 3.0
   
   prefix = 0
   for i in range(min(4, min(len1, len2))):
       if s1[i] == s2[i]:
           prefix += 1
       else:
           break
           
   return jaro + prefix * 0.1 * (1.0 - jaro)

def find_best_dom_element(
   target_text: str,
   dom_elements: List[Dict[str, Any]],
   threshold: float = 0.82
) -> Optional[Dict[str, Any]]:
   """
   Finds the best matching DOM element using normalized fuzzy matching.
   """
   norm_target = normalize_survey_text(target_text)
   best_match = None
   highest_score = 0.0
   
   nav_dictionary = {
       "continue": ["continuer", "weiter", "fortfahren", "next", "suivant", "avanti", "inviare", "submit", "proceder"],
       "yes": ["oui", "ja", "yes", "si"],
       "no": ["non", "nein", "no"]
   }
   
   expanded_targets = [norm_target]
   for intent, synonyms in nav_dictionary.items():
       if norm_target in synonyms or intent == norm_target:
           expanded_targets.extend(synonyms)
           
   for elem in dom_elements:
       elem_text = elem.get("text", "")
       norm_elem = normalize_survey_text(elem_text)
       
       if not norm_elem:
           continue
           
       for candidate_target in expanded_targets:
           if candidate_target == norm_elem or candidate_target in norm_elem:
               return elem
               
           score = jaro_winkler_similarity(candidate_target, norm_elem)
           if score > highest_score:
               highest_score = score
               best_match = elem
               
   if highest_score >= threshold:
       return best_match
   return None

4. Промпт-Інжиніринг для Локальної Vision Моделі (Zero-Hallucination Prompting)
Оптимізація роботи мультимодальної візуальної моделі Gemma 3 4B Vision вимагає урахування її специфічної архітектури: використання замороженого кодувальника SigLIP (фіксована роздільна здатність 896x896), створення 256 візуальних м'яких токенів, інтервальної уваги (5 local sliding window : 1 global attention layer) та контекстного вікна у 128K токенів.
При роботі з веб-елементами (радіогрупи, чекбокси, випадаючі списки) модель схильна плутати вибрані та порожні елементи. Для мінімізації галюцинацій розроблено промпт із примусовим ланцюжком міркувань (Chain-of-Thought, CoT) у форматі JSON.

5. Самолікування та Відновлення після Збоїв (Self-Healing & Resilience)
Захист агента від мережевих збоїв, обривів CDP WebSocket з'єднань, несподіваних перезавантажень сторінок та інтерактивних загороджень (Cloudflare Turnstile, reCAPTCHA) є критичною умовою для забезпечення стабільності сесій.
### Протокол Граціозного Відновлення (Graceful Recovery Protocol)
Система реалізує менеджер транзакційного стану, який зберігає знімок сесії у БД SQLite WAL (survey_session_state) перед виконанням кожної дії. Процес відновлення працює за наступним алгоритмом:
1. Транзакційна Фіксація Кроку: Перед виконанням кліку або введення тексту у БД записуються session_id, step_no, current_url, dom_hash та обрана дія. 2. Детекція Помилки CDP або Тунелю: При розриві SSH-тунелю чи WebSocket з'єднання cdp_client.py запускає цикл автоматичного перепідключення (до 3 спроб із затримкою 2^n секунд). 3. Аналіз Загороджень (Captcha/Turnstile): Перед кожним викликом vision-моделі DOM-дерево перевіряється на наявність сигнатур капчі (cf-turnstile, g-recaptcha, hcaptcha-box, verify you are human).
2. Пауза та Telegram Сповіщення: При виявленні капчі агент не робить галюцинаторних кліків, а переходить у стан CAPTCHA_PAUSE, надсилає сповіщення оператору в Telegram із прямим посиланням на /ops і чекає на ручне розв'язання капчі. 5. Відновлення Контексту: Після відновлення з'єднання або розв'язання капчі агент звіряє поточний dom_hash із записаним у БД state snapshot і продовжує виконання сесії без втрати прогресу опитування.

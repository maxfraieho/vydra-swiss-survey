# Практичний регламент налагодження та тестування (Debugging Playbook)

> **Файл:** `docs/debugging-playbook.md`  
> **Статус:** Обов'язковий регламент відлагодження для `vydra-swiss-survey`  
> **Принцип:** SDD (Spec-Driven Testing) — перевірка реальної поведінки, а не тавтологій.

---

## 4 Кроки вирішення будь-якого інциденту/багу

### 1. Ізольоване відтворення багу (Minimal Reproduction)
- **Заборонено:** Запускати повний сценарій `survey_agent.py` і чекати 10 хвилин розбору логу.
- **Обов'язково:** Написати мінімальний Python-скрипт або тест у `tests/regression/test_<issue_name>.py`, який моделює лише проблемні вхідні дані (наприклад, конкретний рядок DOM, SQL-рядок або заголовок).

### 2. Точна локалізація першопричини (Root Cause Analysis)
- **Заборонено:** Здогадуватись чи маскувати симптоми через порожні `try/except: pass` чи повернення dummy-значень.
- **Обов'язково:** Відкрити реальний кодовий файл, цитувати **файл + точний номер рядка + сигнатуру**, встановити точку зламу контракту.

### 3. Цикл Red/Green тестування (Failing Test -> Fix -> Passing Test)
- Написати тест у `tests/regression/`:
  - **RED State:** Запустити `python3 -m pytest tests/` — тест МУСИТЬ впасти **ДО** внесення правок у кодову базу.
  - **FIX:** Внести мінімально необхідну правку у вихідний код.
  - **GREEN State:** Переконатися, що тест стає пройденим.

### 4. Аналіз зони ураження через GitNexus (Impact Analysis)
- Якщо зміна торкається функції з кількома викликачами (наприклад, `_connect()`, `get_host_rules()`, `bump_rule_outcome()`), виконати:
  ```bash
  python3 scripts/check_gitnexus_impact.py <symbol_name>
  ```
- Переконатися, що суміжні модулі (`rules_api.py`, `survey_agent.py`) не зазнають негативного впливу.

---

## Суворі обмеження тестування

1. **Жодних тавтологічних асертів:** Заборонено тести на кшталт `assert len(x) > 0` або `assert x == x`. Тест повинен перевіряти **наслідки поведінки** (правильний каскад пріоритетів, збереження WAL-режиму, відмова при відсутності елемента).
2. **Легкий гарячий шлях (Hot Path Protection):** Функції `survey_agent.py`, `get_host_rules()`, `bump_rule_outcome()` є гарячим шляхом виконання. Вони МУСЯТЬ залишатися синхронними та легкими. Жодних викликів pytest, важкого синтезу файлів або блокуючих мережевих запитів під час проходження опитування.

## 2. Оцінка методики навчання агента (тутор-LLM + людина)

Оцінка за `docs/for-agents/teaching-methodology.md` (P1–P5, тріо «Агент — Тутор-людина — Асистент», життєвий цикл shadow → active при N ≥ 3).

### 2.1 Сильні місця (не ламати)
- **Розділення швидкостей** (секунди / живий прогін / хвилини) — правильна архітектурна вісь; гарячий шлях чистий.
- **4-рівнева ізоляція scope** + `structure_hash` без текстів — правильний захист від «правило з одного сайту зламало інший».
- **Емпіричний гейт промоції N ≥ 3** замість довіри до одного кліку.
- **P1 guard на токени ≤ 3 символів** — саме той клас помилок, що вбиває фаззі-матч на `oui/non/ja`.

### 2.2 Прогалини

| # | Прогалина | Наслідок | Пропозиція |
|---|---|---|---|
| G1 | Тутор-LLM високого рівня в методиці **не описаний як окрема роль** — є лише «Асистент, який формалізує». Немає контракту «коли кличемо велику модель» | Дорога модель або не кличеться, або кличеться на все | Ввести роль **Тутор-LLM (Reviewer)** з тригерами: 2 підряд `loss` того самого `structure_hash`; агент `confidence < 0.6`; конфлікт правил; нове provider-сімейство. Решта — без неї |
| G2 | Немає **зворотного зв'язку від результату до промпта**: `wins/losses` живлять лише промоцію правил | Vision-CoT не вчиться на систематичних помилках | Артефакт `lessons.md` (12–20 рядків, автогенерований з топ-N повторюваних losses) інжектиться у CoT-промпт; ревізія раз на 50 прогонів, benchmark 10 кейсів як гейт |
| G3 | **Немає negative-cache**: провал не фіксує «як не робити» | Агент повторює ту саму помилку до 3-го провалу | `status='quarantine'` при 2 losses і 0 wins: правило не застосовується, але лишається як anti-pattern у поясненні для тутора |
| G4 | Овверайд тутора не фіксує **причину** (лише правильну дію) | Неможливо агрегувати класи помилок і навчати | Обов'язкове поле `reason_code` (enum: `wrong_target`, `text_mismatch`, `persona_conflict`, `timing`, `captcha`, `layout_change`) — 1 тап у UI, дає статистику класів |
| G5 | Немає **метрик навчання**, лише тести | Не видно, чи система реально вчиться | Дашборд: HITL-інтервенцій на прогін (тренд ↓), median time-to-override, shadow→active за тиждень, % прогонів без тутора, top-5 `reason_code` |
| G6 | Немає **calibration-перевірки тутора-людини** | Помилковий оверрайд стає правилом | Кожен 10-й оверрайд дублюється на Тутора-LLM; розбіжність → правило лишається `shadow` і йде в `async_review_queue` з поміткою «спірне» |

### 2.3 Цільова петля навчання

```text
прогін ─▶ агент (Gemma Vision CoT)
             │ confidence < 0.6 / 2× loss / конфлікт
             ▼
        Тутор-LLM (Reviewer, хвилини)  ──▶ пропозиція + reason_code
             │ згода                        │ розбіжність
             ▼                              ▼
     людина: 1 тап «Підтвердити»      «спірне» → черга розгляду
             ▼
     rule: shadow ─(N≥3 wins)─▶ active ; 2 losses ─▶ quarantine
             ▼
     lessons.md ──▶ CoT-промпт (гейт: benchmark 10/10)
```

## 3. Інтерфейс: перейменування і зміни в цьому ж ключі

### 3.1 Мова інтерфейсу — людська, без внутрішніх абревіатур

| Зараз | Пропозиція | Чому |
|---|---|---|
| `Ops (HITL)` | **«Пульт оператора»** (шлях `/ops` лишається; підзаголовок «живий прогін і підказки агенту») | HITL — жаргон; оператор не має розшифровувати |
| `Прогони (Traces)` | **«Історія прогонів»** | «Traces» дублює переклад |
| `Звіт (Report)` | **«Звіт»** | те саме |
| `Гейт хоста` | **«Допуск сайту»** | «гейт» нічого не каже людині |
| `Правила` | **«Навички агента»** | у моделі «навчання» правило = навичка; узгоджує термін з методикою |
| `Конфлікти` | **«Суперечності навичок»** + бейдж-лічильник | видно проблему без заходу |
| `Порівняння` | **«Порівняти навички»** | дієслово = дія |
| `status: shadow / active` | **«на випробуванні» / «діє»** (+ `quarantine` → **«вимкнено після провалів»**) | оператор мусить розуміти, що правило ще не працює |
| `structure_hash` | **«відпечаток сторінки»** (повний хеш — у деталях) | |
| `waiting_verification` | **«чекає на вас»** (акцентний колір + звук/пуш) | це єдиний стан, що вимагає людини |

### 3.2 Нова навігація (3 секції, вхід на пульт)

```text
Робота        → /ops        Пульт оператора      (DEFAULT, бейдж «чекає на вас»)
                /traces     Історія прогонів
                /report      Звіт
Навчання      → /rules      Навички агента
                /rules/conflicts  Суперечності   (бейдж-лічильник)
                /queue      Черга на розгляд     (async_review_queue — окремий екран, зараз його немає)
Налаштування  → /settings   Сайти, персони, патерни
                /gate       Допуск сайту
```

### 3.3 Пульт оператора — цільова структура (замість монолітного `SurveyOps.tsx`)

Порядок згори вниз = пріоритет уваги оператора:

1. **`ops/AttentionCard.tsx`** — єдина картка «Треба ваша дія»: скріншот з SVG-оверлеєм, 2–4 великі кнопки (≥ 44 px), таймер очікування, `reason_code`-чіпи одним тапом. Якщо дії не потрібно — картки немає (не «порожній стан», а відсутність).
2. **`ops/AgentIntent.tsx`** — «Що агент збирається зробити і чому»: цільовий текст + 1–2 рядки CoT + шкала впевненості. Це вчить людину довіряти/не довіряти.
3. **`ops/StatusHeader.tsx`** — стан, сайт, персона, прогрес (`ProgressBar`), кнопки «Пауза / Стоп».
4. **`ops/StepTimeline.tsx`** — крок за кроком, з позначкою «тут вас питали» і «тут правило застосовано (яке)».
5. **`ops/LaunchForm.tsx`** — запуск (згорнуто, коли прогін активний).
6. **`ops/TutorSuggestion.tsx`** — блок Тутора-LLM: пропозиція, згода/незгода з агентом, кнопка «Підтвердити» / «Спірне».

Правила для всіх шести: 0 HEX (тільки `statusColor` з `ui/tokens.ts`), ≤ 250 рядків, кольори стану лише через `StatusPill`.

### 3.4 Мікро-правила UX навчання
- **Одна дія — один тап.** Оверрайд не має відкривати модалку з формою; `reason_code` — чіпи в тій самій картці.
- **Показувати ціну очікування:** «агент стоїть 2 хв 14 с» — це мотивує реакцію краще за нотифікацію.
- **Після оверрайду — фідбек:** тост «Створено навичку «на випробуванні» (1/3 успішних прогонів)» з посиланням. Людина бачить, що її клік не зник.
- **Пуш у Telegram — з дією:** кнопки прямо в повідомленні (де можливо), а не лише лінк.
- **Мобільний фокус:** пульт мусить бути повністю робочим на 390 px — саме зі смартфона його й дивлять.

## 2. Блок A — авторизація з людською поведінкою (головний)

### A0. Профіль поведінки (створити ДО прогону)
`web/../agent/behavior/human_profile.json` (або відповідне місце в поточній структурі):

```json
{
  "typing": { "cps_mean": 4.2, "cps_jitter": 1.6, "mistake_rate": 0.03, "backspace_delay_ms": [120, 340] },
  "pause": { "before_field_ms": [400, 1800], "after_field_ms": [250, 900], "read_page_ms": [1200, 4000] },
  "mouse": { "path": "bezier", "overshoot_px": [2, 14], "settle_ms": [60, 180] },
  "scroll": { "steps": [3, 9], "step_px": [80, 260], "step_delay_ms": [90, 400] },
  "idle": { "micro_pause_prob": 0.18, "micro_pause_ms": [700, 2600] }
}
```

Правило: **жоден ввід не миттєвий**. Заповнення поля = focus → пауза → посимвольний ввід
з джитером → інколи помилка+backspace → пауза → blur. Клік = рух курсору по кривій з
невеликим перельотом, не телепорт до координат.

### A1. Гігієна сесії (перевірити перед першим запитом)
- [ ] реальний `User-Agent`, узгоджений з платформою браузера (не headless-дефолт)
- [ ] `navigator.webdriver` не виставлений
- [ ] узгоджені `Accept-Language`, timezone, locale, розмір вікна і `devicePixelRatio`
- [ ] cookies/`storageState` персистяться між прогонами (не чиста сесія щоразу)
- [ ] один стабільний IP/вихід на весь сеанс — без стрибків посеред логіну
- [ ] заходити на цільову сторінку **не напряму**: спершу головна → пауза → навігація по посиланнях

Evidence: `evidence/auth/01-session-hygiene.txt` (дамп перевірених значень) + скріншот стартової.

### A2. Прохід логіну
Кроки з фіксацією скріншота на кожному:
1. Відкрити головну, `read_page_ms` пауза, скрол.
2. Перейти до логіну по посиланню в UI.
3. Ввести логін (людський темп) → пауза → пароль → пауза → submit.
4. Зафіксувати відповідь: успіх / капча / бот-фільтр / 2FA / e-mail-код.

Evidence: `evidence/auth/02-login-*.png`, HAR або лог запитів `evidence/auth/02-network.txt`.

### A3. Капча і бот-фільтр — обов'язково через HITL, не автообхід
**Заборонено:** будь-які спроби автоматично розв'язувати капчу, обходити фільтр,
підміняти токени капчі або використовувати сторонні сервіси розв'язання.
Правильна поведінка = **зупинка і передача людині**:

- Детектор капчі/фільтра → створити `AgentIntent` зі `state: "waiting_verification"`,
  `reason_code: "captcha_detected"` (або `"bot_filter_detected"`), bbox на елементі капчі.
- UI: `AttentionCard` показує причину, скріншот у `Viewport`, таймер очікування.
- Людина розв'язує капчу **прямо у fullscreen-режимі Viewport** (це і є ключовий тест 020) —
  без виходу з повного екрана, без переходу на інший екран.
- Після підтвердження — агент продовжує з того ж кроку, сесія не втрачається.

Перевірити окремо:
- [ ] капча детектується, а не «зависає» без причини
- [ ] у fullscreen видно капчу читабельно (зум/пан працює)
- [ ] ввід у капчу з fullscreen доходить до сторінки
- [ ] після розв'язання прогін продовжується, `trace` містить крок з `reason_code`
- [ ] повторний прогін використовує збережену сесію і капчу не показує

Evidence: `evidence/auth/03-captcha-fullscreen.png`, `03-after-solve.png`,
`03-trace.json` (крок із `reason_code`).

### A4. Антипатерни — переконатися, що їх НЕ робимо
- [ ] нема паралельних логінів з однієї сесії
- [ ] нема ретраю логіну частіше ніж 1 раз / 60+ с з експоненційним backoff
- [ ] нема послідовності запитів з рівними інтервалами (детектується як бот)
- [ ] нема заповнення hidden/honeypot-полів
- [ ] нема сабміту форми раніше ніж через 3 с після її появи

## 1. Повноекранний інтерактивний браузер (головне)

Зараз скріншот/стрім цільового сайту живе у картці всередині `SurveyOps.tsx` і на 390 px займає ~30 % висоти — оператор не бачить, що насправді на сторінці, і не може точно вказати елемент. Це головний блокер навчання агента.

### 1.1. Три режими одного компонента `ops/Viewport.tsx`

| Режим | Коли | Поведінка |
|---|---|---|
| `inline` | за замовчуванням | картка в потоці, співвідношення 16:10, `object-fit: contain` |
| `focus` | клік на кадрі / кнопка «Розгорнути» | займає всю робочу область (під TopNav), таймлайн і чат ховаються у нижній лист (`Sheet`) |
| `fullscreen` | кнопка ⛶ / `F` | `requestFullscreen()` на контейнері + `screen.orientation.lock('landscape')` на мобільному (fallback — CSS-режим `position: fixed; inset: 0`) |

Стан режиму — в URL (`?view=focus`), щоб перезавантаження і deep-link не губили контекст. Вихід — `Esc`, свайп вниз, кнопка ✕.

### 1.2. Обов'язкові елементи оверлея у `focus`/`fullscreen`

- **Верхня смуга (48 px, напівпрозора):** статус-піл (`StatusPill`), поточний URL (обрізаний посередині), крок «3/12», кнопка ⛶/✕.
- **Нижня смуга дій (56 px, safe-area-inset):** ті самі 1-tap кнопки, що в `AttentionCard` — «Підтвердити», «Виправити», «Пауза». Оператор не має виходити з повного екрана, щоб відповісти.
- **Шар підсвітки:** прозорий `<canvas>`/absolute-div поверх кадру, що малює bbox елемента, на який агент дивиться (з `agent_intent.target_bbox`) + режим «вкажи елемент» (tap → нормалізовані координати `{x,y}` у 0..1 йдуть у `human_correction`).
- **Пінч-зум і пан** (`touch-action: none` + матриця transform), бо капчі й дрібні радіо-кнопки читаються тільки в зумі.

### 1.3. Технічні інваріанти

- Кадр рендериться в `<img>` з `decoding="async"` + `key=frame_id`; без ре-монтування контейнера (інакше fullscreen злітає).
- Нові кадри не скидають зум/пан, поки користувач у режимі «вкажи елемент».
- Ніяких HEX у компоненті: оверлеї — `color-mix(in oklab, var(--color-bg-elevated) 80%, transparent)`.
- Компонент ≤ 220 рядків; логіка режиму — `ops/useViewportMode.ts`.

## 2. Ревізія вкладок: що працює, що зайве

Оцінка з точки зору однієї мети — **навчити агента правильно поводитись на цільовому вебресурсі**.

| Вкладка | Стан у коді | Вердикт | Дія |
|---|---|---|---|
| **Ops (HITL)** → «Пульт оператора» | працює, але монолітна (1563 рядки) | ядро продукту | розбити + п.1 |
| **Traces / Прогони** | працює, читається | потрібна: джерело «уроків» | залишити, додати фільтр «тільки з правками людини» |
| **Rules → «Навички агента»** | працює | потрібна | залишити, перейменувати статуси |
| **Host Gate / «Гейт хоста»** | по суті список дозволених домен + прапорці; окремий екран для 5 полів | **не окремий екран** | згорнути у `Settings → Доступи` + інлайн-банер у Пульті «домен не дозволений → Дозволити» (одна кнопка). Економія: −1 пункт нав, −356 рядків |
| **Compare / «Порівняння»** | таблиця двох прогонів, руками не використовується (нема входу з Traces) | **низька цінність зараз** | не видаляти, а перетворити в дію: у Прогонах чекбокси 2 рядків → кнопка «Порівняти» відкриває `MasterDetail`-панель. Прибрати з нав-меню |
| **Conflicts / «Конфлікти правил»** | логіка є, але екран мертвий бо нема тригера | **критично потрібна**, просто захована | вивести як бейдж-лічильник біля «Навички агента» + інлайн-блок «конфліктує з правилом X → лишити нове / лишити старе / об'єднати» прямо в деталі правила. Окремий екран — тільки як «усі конфлікти» |
| **Report / «Звіт»** | працює | потрібна для людини-тутора | залишити |
| **Patterns / Providers / Personas** | налаштування | залишити у Settings-табах, з нав прибрати |

**Наслідок для IA — 3 секції, 5 пунктів:**

```
Робота     → /ops      Пульт оператора   (default landing)
             /traces    Прогони
Навчання   → /rules     Навички агента   [бейдж конфліктів]
             /report     Звіт
Налаштування → /settings (Доступи · Джерела · Персони · Провайдери)
```

Правило: **екран існує тільки якщо на нього є вхід з робочого потоку.** Compare і Conflicts мали екран без входу — саме тому «здавалося, що не працює».

## 3. Помірні покращення, які реально економлять час оператора

1. **Ціна очікування** — у `AttentionCard` таймер «агент чекає 00:42» + звук/вібро на новий запит.
2. **Причина правки** — при «Виправити» обов'язковий `reason_code` (селектор з 6 варіантів) → без нього немає уроку для тутор-LLM.
3. **Впевненість агента** — один рядок: `AgentIntent` показує намір + `ProgressBar` впевненості; < 0.6 автоматично піднімає запит до людини.
4. **Клавіатура на десктопі**: `1` підтвердити, `2` виправити, `Space` пауза, `F` fullscreen.
5. **Порожні стани** один `<EmptyState>` з дією, а не сирий текст.

Не робимо (надмірне): темна/світла тема-перемикач, анімації переходів між екранами, кастомні графіки, drag-n-drop таймлайну.

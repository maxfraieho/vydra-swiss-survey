# /sdd:* slash-команди для vydra-swiss-survey

## Встановлення (Claude Code — перевірено)

Скопіюй директорію `.claude/commands/sdd/` у корінь репозиторію (файли вже в правильній структурі в цьому архіві). Це дасть 9 команд:

- `/sdd:feature <назва> — <опис>` → Шаблон 1 (Нова Фіча)
- `/sdd:bugfix <опис проблеми>` → Шаблон 2 (Виправлення Багу)
- `/sdd:refactor <модуль>` → Шаблон 3 (Рефакторинг / Оптимізація)
- `/sdd:integration <сервіс>` → Шаблон 4 (Інтеграція Сервісу / API)
- `/sdd:teaching <профіль> <host> — <опис>` → Шаблон 5 (Навчання Агента)
- `/sdd:clarify <опис ідеї>` → Шаблон 7 (Зняття Неоднозначностей)
- `/sdd:research <тема>` → Шаблон 6 (Глибоке Дослідження)
- `/sdd:audit <модуль/spec>` → Шаблон 8 (Аудит Spec-Drift)
- `/sdd:verify` → Шаблон 9 (Комплексна Верифікація Системи)

Команди — проєктні (`.claude/commands/`), тобто закомічені в репо й доступні кожному, хто його клонує, а не тільки тобі особисто.

Кожна команда: (1) читає відповідний Шаблон з `docs/for-agents/sdd-development-methodology.md` замість того, щоб дублювати його текст — єдине джерело правди, без ризику розходження; (2) явно нагадує про `.specify/constitution.md` і MUST-правила з `AGENTS.md`; (3) вимагає в фінальному звіті конкретні докази виконання (файл:рядок, вивід тестів, вивід `sdd_verify.sh`), а не просто "зроблено".

## Щодо agy

**Оновлено 2026-08-17, підтверджені факти** (deep research + живий SSH-аудит dev-184, деталі в `specs/021-multiagent-sdd-extension/plan.md`):

- Стара директорія `.agent/commands/` з `$ARGUMENTS`-підстановкою (текстова інтерполяція макросів) — **офіційно deprecated** починаючи з Antigravity CLI v1.20.5+.
- Сучасний і єдиний механізм — відкритий стандарт **Agent Skills**: будь-яка директорія `.agents/skills/<skill-name>/` (чи `.agent/skills/<skill-name>/`) з файлом `SKILL.md`, що має YAML-frontmatter (`name`, `description`), **автоматично реєструється** в TUI як `/<skill-name>`.
- **Механічної підстановки змінних (`$ARGUMENTS`) немає.** Замість цього AGY застосовує модель Progressive Disclosure: на старті сесії завантажуються лише метадані (`name`+`description`) усіх скілів — це мінімізує витрати токенів. Повний текст `SKILL.md` активується семантично (при виклику команди чи релевантному контексті), після чого модель сама парсить весь введений користувачем текст і параметри задачі — без жодного шаблонного `$1`/`$ARGUMENTS`.

Практичний наслідок: у проєкті розгорнуто 5 окремих skill-файлів (`.agents/skills/sdd-{feature,bugfix,refactor,integration,teaching}/SKILL.md`) замість одного загального `sdd-workflow` — причина в тому ж Progressive Disclosure: одне загальне `description` про "методологію" не дає моделі AGY сигналу маршрутизації між bugfix і refactor, тоді як 5 різних `description`-полів дають 5 чітких тригерів. Ці ж самі файли одночасно обслуговують і AGY, і Codex CLI (нижче) — жодного дублювання логіки.

Верифікація на реальному AGY (телефон/AGY2/AGY3) — окрема задача після синхронізації гілки, `agy` не встановлений на dev-184.

## Codex CLI

Codex CLI (`codex-cli`, встановлений на dev-184) нативно читає `AGENTS.md` як пріоритетний контекст на старті сесії — до першого запиту до моделі.

Для slash-команд Codex підтримує **два незалежні механізми**, обидва задіяні в цьому проєкті:

1. **Prompt-шаблони** (`.codex/prompts/*.md`, проєктні, або `~/.codex/prompts/*.md`, глобальні) — реєструються в TUI-меню як `/<filename-без-.md>`. Синтаксис підстановки: `$1`…`$9` (позиційні аргументи), `$ARGUMENTS` (весь рядок), `$$` (екранування `$`). У проєкті розгорнуто 5 тонких лаунчерів `.codex/prompts/sdd-{feature,bugfix,refactor,integration,teaching}.md`, кожен лише посилається на відповідний файл у `.agents/skills/sdd-*/SKILL.md` — методологія не дублюється.
2. **Agent Skills** (`.agents/skills/<name>/SKILL.md`) — той самий відкритий стандарт, що й AGY. Codex може активувати скіл семантично, без слеш-команди.

Статус верифікації (2026-08-17): наявність `.codex/prompts/`-механізму на встановленій версії (`codex-cli 0.124.0`) **не підтверджена в TUI живим тестом** — `codex exec`/`codex --help` не дають CLI-способу перелічити зареєстровані prompt-команди без інтерактивної TUI-сесії. Файли створені (гібридна стратегія — якщо TUI-меню не підхопить `.codex/prompts/`, скіл-шлях лишається робочим). Потрібна ручна перевірка: відкрити `codex` у корені репозиторію, перевірити `/sdd-feature` у списку команд.

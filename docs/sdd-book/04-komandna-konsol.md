# Розділ 4. Командна консоль

Одна дія (наприклад, "почни нову фічу") — три різні способи виклику,
залежно від того, яким агентом працюєш. Логіка однакова у всіх трьох —
кожен читає той самий `docs/for-agents/sdd-development-methodology.md`,
просто механізм виклику інший.

## Claude Code — `/sdd:*` (9 команд)

Проєктні команди, `.claude/commands/sdd/`, закомічені в репо:

| Команда | Коли використовувати |
|---|---|
| `/sdd:feature <назва> — <опис>` | Нова фіча, endpoint, UI-компонент |
| `/sdd:bugfix <опис проблеми>` | Баг/інцидент — root cause спершу, RED-тест до фіксу |
| `/sdd:refactor <модуль>` | Рефакторинг/оптимізація без зламу контракту |
| `/sdd:integration <сервіс>` | Підключення зовнішнього API/сервісу |
| `/sdd:teaching <профіль> <host> — <опис>` | Формалізація HITL-корекцій в shadow-правило |
| `/sdd:clarify <опис ідеї>` | Перед складним `plan.md` — зняти неоднозначності |
| `/sdd:research <тема>` | Глибоке дослідження, готує промпт-артефакт |
| `/sdd:audit <модуль/spec>` | Перевірити чи код не розійшовся зі specs (spec-drift) |
| `/sdd:verify` | Прогнати `bin/sdd_verify.sh` + системні інваріанти |

## Codex CLI — `.codex/prompts/`

П'ять тонких лаунчерів (`sdd-feature`, `sdd-bugfix`, `sdd-refactor`,
`sdd-integration`, `sdd-teaching`), кожен приймає аргумент так само, як
Claude:

```
/sdd-feature лічильник активних опитувань — показати кількість активних
```

Кожен prompt-файл — усього 4 рядки, лише посилається на відповідний
`.agents/skills/sdd-*/SKILL.md`, не дублює текст методології.

⚠️ **Статус (2026-08-17):** файли створені й задеплоєні, але наявність
цього меню в TUI на встановленій версії (`codex-cli 0.124.0`) не
підтверджена автоматизованим тестом — `codex exec`/`--help` не дають
способу перелічити prompt-команди без інтерактивної сесії. Якщо відкриєш
`codex` в репо і НЕ побачиш `/sdd-feature` в списку — це відомий,
задокументований розрив (не твоя помилка налаштування), скіл-шлях
(нижче) лишається робочим fallback.

## AGY (Antigravity CLI) — Agent Skills, без слеш-синтаксису

AGY НЕ має механізму текстової підстановки на кшталт `$ARGUMENTS`. Замість
цього — Progressive Disclosure: на старті сесії AGY бачить лише `name` +
`description` кожного скіла з `.agents/skills/`, повний текст активується
семантично. Практично це означає: просто сформулюй задачу природною
мовою, AGY сам розпізнає релевантний скіл (`sdd-feature`, `sdd-bugfix`
тощо) за описом і активує його — не треба вгадувати точний
слеш-синтаксис.

Стара директорія `.agent/commands/` з `$ARGUMENTS` — офіційно deprecated
з AGY v1.20.5+, не використовуй її як довідку.

## Спільна основа для всіх трьох

Незалежно від того, хто викликав — Claude, Codex чи AGY — усі читають ОДИН
і той самий `docs/for-agents/sdd-development-methodology.md` і одну й ту
саму `.specify/constitution.md`. Це навмисно: якщо два агенти по черзі
працюють над однією фічею, вони не можуть отримати різні інструкції.

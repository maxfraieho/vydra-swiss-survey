# Розділ 2. 15-хвилинний Quickstart

Наскрізний приклад: додаємо гіпотетичну дрібну фічу — "показати лічильник
активних опитувань на дашборді". Показуємо весь цикл через Claude Code
(`/sdd:feature`), той самий цикл в Codex CLI/AGY виглядає інакше лише на
рівні "як покликати", суть однакова — див. Розділ 4.

## Крок 1 — Формулюєш намір

У Claude Code, в корені репо `vydra-swiss-survey`:

```
/sdd:feature лічильник активних опитувань — показати кількість активних
опитувань у шапці Astryx dashboard, оновлюється кожні 30с
```

Що відбувається всередині (не треба робити руками — агент виконує сам):

1. Агент читає `docs/for-agents/sdd-development-methodology.md`, розділ
   "ШАБЛОН 1", і `.specify/constitution.md` — щоб не порушити інваріанти
   (hot path < 5ms і т.д.).
2. Дивиться `ls specs/` — щоб визначити вільний номер (не вигадує з голови).
3. Створює `specs/022-active-survey-counter/spec.md` — з user story,
   Given-When-Then сценаріями.

## Крок 2 — Перевіряєш spec.md

Це найважливіший момент людського контролю. Відкриваєш
`specs/022-active-survey-counter/spec.md`, читаєш Given-When-Then:

```
Given дашборд Astryx відкритий
When є 3 активні опитування
Then лічильник показує "3", оновлюється без перезавантаження сторінки
```

Якщо тут щось не так — правиш ЗАРАЗ, до коду. Дешевше виправити речення,
ніж потім переписувати компонент.

## Крок 3 — Агент планує і реалізує

Після твого підтвердження — той самий `/sdd:feature` (або наступний виклик
з посиланням на цю ж фічу) продовжує: план, `impact()`-аналіз через
GitNexus (щоб не зламати нічого суміжного), реалізація, тести.

## Крок 4 — Ворота верифікації

Перед комітом агент (МУСИТЬ, за `AGENTS.md`) запускає:

```bash
bash bin/sdd_verify.sh --gate
```

Це перевіряє: чи всі артефакти для поточної фази присутні (`spec.md`,
`plan.md`, `tasks.md`), чи `branch` у `.specify/feature.json` збігається з
поточною гілкою. Якщо чогось нема — команда падає з точною назвою
відсутнього файлу, коміт не проходить.

## Крок 5 — Коміт

Кожен фазовий перехід — окремий коміт (`spec:`, `plan:`, `tasks:`,
`impl:` префікс). Це не бюрократія заради бюрократії: якщо завтра інший
агент (скажімо, Codex) підхопить цю фічу, він читає
`.specify/feature.json` + `git log -n 1 --stat` і одразу бачить, на якому
кроці зупинились — без "згадування" з діалогу, якого він не бачив.

## Що ти щойно вивчив

- `spec.md` / `plan.md` / `tasks.md` — три файли одного циклу (Розділ 3).
- `/sdd:feature` — одна з 9 команд (Розділ 4).
- `--gate` — L3 Validator Gate (Розділ 5).
- `.specify/feature.json` — точка передачі контексту між агентами (Розділ 5).
